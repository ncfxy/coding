LeetCode 把「最短回文串」归类到 **滚动哈希（Rolling Hash）** 标签下，是因为这道题除了可以用 KMP 前缀函数解决，还可以用 **字符串哈希** 在 `O(n)` 时间内找到最长回文前缀。滚动哈希提供了一种与 KMP 不同的思路，所以被列为该题的解法之一。

下面详细解释滚动哈希与这道题的关系。

---

## 1. 滚动哈希是什么？

滚动哈希（Rabin-Karp 算法的核心）是一种快速比较字符串子串是否相等的方法。

它的基本思想是：
- 把字符串看作一个 `base` 进制的数，例如 `base = 131` 或 `13331`。
- 预处理出前缀哈希数组 `h[i]`，表示前 `i` 个字符的哈希值。
- 同时预处理 `base` 的幂次 `p[i]`。
- 这样，任意子串 `s[l..r]` 的哈希值可以在 `O(1)` 时间内计算出来：
  ```
  hash(l, r) = h[r+1] - h[l] * p[r-l+1]
  ```
- 通过比较两个子串的哈希值，就能判断它们是否相等（有极小概率碰撞，可用双哈希避免）。

---

## 2. 这道题与滚动哈希的关系

题目要求：在 `s` 前面添加最少的字符，使其变成回文串。  
等价于：**找到 `s` 的最长回文前缀**。

设 `s` 长度为 `n`，最长回文前缀长度为 `l`，则答案是：
```
reverse(s[l..n-1]) + s
```

如何用滚动哈希快速找到 `l`？

一个字符串是回文，意味着它正着读和反着读一样。  
对于 `s` 的前缀 `s[0..l-1]`，它如果是回文，则：
```
s[0..l-1] == reverse(s[0..l-1])
```

设 `rev = reverse(s)`。  
那么 `reverse(s[0..l-1])` 就是 `rev` 中从 `n-l` 到 `n-1` 的子串。  
所以判断条件变为：
```
s[0..l-1] == rev[n-l..n-1]
```

我们可以预处理：
- `s` 的前缀哈希 `h_s`
- `rev` 的前缀哈希 `h_rev`

然后从 `l = n` 到 `1` 枚举前缀长度，用 `O(1)` 时间比较：
```
hash_s(0, l-1) == hash_rev(n-l, n-1)
```
第一个满足的 `l` 就是最长回文前缀长度。

找到 `l` 后，答案就是 `rev.substr(0, n-l) + s`。

---

## 3. 具体步骤

1. 如果 `s` 为空，返回 `""`。
2. 计算 `rev = reverse(s)`。
3. 预处理 `s` 和 `rev` 的前缀哈希数组，以及 `base` 的幂次数组。
4. 从 `l = n` 递减到 `1`，检查 `s[0..l-1]` 是否回文：
   - 计算 `hash_s(0, l-1)`
   - 计算 `hash_rev(n-l, n-1)`
   - 如果相等，则 `l` 就是最长回文前缀长度，跳出循环。
5. 返回 `rev.substr(0, n-l) + s`。


---

## 5. 为什么 LeetCode 打「滚动哈希」标签？

- 这道题的标准解法有：
  - KMP 前缀函数（`O(n)`）
  - 滚动哈希（`O(n)`）
  - Manacher 算法（`O(n)`）
- 滚动哈希提供了一种不依赖 KMP 的线性时间解法，思路直观：枚举前缀长度，用哈希 `O(1)` 判断是否为回文。
- 因此 LeetCode 将其归入「滚动哈希」标签，表示这是一种可行的解题技巧。

---

## 6. 注意事项

- 单哈希有极小概率碰撞，实际面试中可提一下，若需要绝对正确可用双哈希（两个模数）或改用 KMP。
- 滚动哈希的时间复杂度为 `O(n)`，空间复杂度为 `O(n)`。
- 由于需要从 `n` 到 `1` 枚举，最坏情况下会检查所有长度，但每次检查是 `O(1)`，所以总时间仍是 `O(n)`。

总结：滚动哈希与这道题的关系在于——它可以帮助我们快速比较 `s` 的前缀和 `s` 的反转的对应后缀是否相等，从而在线性时间内找到最长回文前缀，进而构造最短回文串。
