# 二叉搜索树（BST）

二叉搜索树（BST，Binary Search Tree）是二叉树中最具实用价值的变体。它在普通二叉树的基础上，通过一个简单的**“左小右大”**的排序约束，将“查找”效率从遍历的 O(N) 提升到了平均 O(log N)。

如果说普通二叉树是骨架，那 BST 就是赋予了骨架**“可二分查找”的灵魂**。下面我深入拆解它的核心机制：

### 1. 核心定义（有序性）
对于 BST 中的**任意一个节点**，其子树必须满足：

-   左子树上**所有**节点的值 **<** 根节点的值。
-   右子树上**所有**节点的值 **>** 根节点的值。
-   左右子树也分别为 BST。

**关键推论**：对 BST 进行**中序遍历（左→根→右）**，得到的结果一定是**严格升序**的数组。这也是验证一棵树是否为 BST 的最直接方法。

---

### 2. 三大核心操作（查找、插入、删除）
这三种操作都充分利用了二分思想，每次比较都能排除掉一半的子树。

-   **查找（Search）**：从根开始，目标值大于当前节点则向右走，小于则向左走，等于则命中。最理想情况下，路径长度就是树的高度。
-   **插入（Insert）**：和查找路径一致，直到遇到空位置（`null`），就在该位置挂上新节点。**注意**：BST 一般不允许插入重复值（如有重复需求，可在节点增加计数 `count` 字段）。
-   **删除（Delete）**：最复杂，分三种情况（**面试高频**）：
    -   **叶子节点**：直接删除，将其父节点对应的指针置空。
    -   **有一个子节点**：让该节点的唯一子节点“替父从军”，直接顶替被删除节点的位置。
    -   **有两个子节点**（核心难点）：**不能直接删掉**。需要找到该节点的**中序后继**（右子树中的最小值）或**中序前驱**（左子树中的最大值），用这个节点的值覆盖待删除节点，然后去子树中递归删除那个被拿来顶替的节点（此时这个被删的节点一定满足情况1或2）。

---

### 3. 时间复杂度（致命的“偏科”）
-   **平均情况**：如果插入顺序是随机的，树的高度约为 **O(log N)**，因此查找、插入、删除的时间复杂度均为 **O(log N)**。
-   **最坏情况（痛点）**：如果插入的数据是**有序的**（如 1, 2, 3, 4, 5），BST 会退化成一条**链表**（只有右孩子）。此时树的高度变为 N，所有操作的时间复杂度瞬间降为 **O(N)**。

---

### 4. 如何验证一棵树是 BST？（不要掉坑）
很多人以为“左孩子 < 父节点 < 右孩子”就够了，这是**错误**的，因为还要保证“左子树的最大值 < 父节点 < 右子树的最小值”。

正确的解法有两种：

1.  **中序遍历法**：中序遍历结果必须严格升序，没有相等元素。
2.  **传递边界法（递归）**：给每个节点传递一个合法的取值范围 `(min, max)`。例如，根节点取值范围是 `(-∞, +∞)`，其左孩子的范围必须是 `(-∞, root.val)`，右孩子是 `(root.val, +∞)`。

---

### 5. 致命缺陷与进化方向
由于 BST 无法自平衡，计算机科学家们发明了**平衡二叉搜索树**来解决退化问题：

-   **AVL 树**：严格平衡（左右高度差 ≤ 1），查找极快，但插入删除时的旋转调整成本较高。
-   **红黑树（Red-Black Tree）**：弱平衡（近似平衡），插入删除效率更高。**Java 的 `TreeMap`、`TreeSet` 以及 C++ 的 `std::map` 底层都是红黑树**。
-   **B 树 / B+ 树**：多路平衡搜索树，专门用于磁盘存储（数据库索引），因为磁盘 IO 读取数据块时，多叉树能显著降低树高。
