# 压缩字典树（Radix Tree / Patricia Trie）

压缩字典树的核心改造只有一条：**消除所有“只有一个孩子”的中间节点，把单挑的链条合并成一条边（Edge）上的字符串。**

---

### 1. 直观对比：从“单字符跳”到“字符串跳”

假设我们要存储三个单词：`test`、`testing`、`team`。

-   **普通 Trie**：必须一个字母一个字母地拆开。路径是 `t->e->s->t...`，为了区分 `test` 和 `testing`，中间会产生大量仅为了“搭桥”而存在的冗余节点。
-   **压缩 Trie（Radix Tree）**：会直接把“单行道”压缩成一块。
    最终的结构长这样：

```
          (根)
           |
         "te"   <--- 压缩了公共前缀
         /   \
      "st"   "am"  <--- 在此处分叉
      /   \     |
    (end) "ing" (end)  <--- "test"结束，以及"testing"的剩余部分
           |
         (end)  <--- "testing"结束
```

**解读**：
根节点直接挂载边 `"te"`，而不是 `t` 和 `e`。在 `"te"` 节点下，因为 `test...` 和 `team...` 分叉了，所以分出了 `"st"` 和 `"am"` 两条边。`test` 单词直接在 `"st"` 处结束，而 `testing` 则在 `"st"` 后面再接一条边 `"ing"`。

这样一来，原本需要 **10+** 个节点存储的结构，现在仅需 **5** 个节点就搞定了，内存节省非常可观。

---

### 2. 核心机制：边分裂（Edge Split）

压缩树最精妙也最复杂的操作是**插入时的边分裂**。我们举个新例子：上述树中已经存在 `team`（路径 `te` -> `am`），现在我们要插入一个新单词 `tea`。

1. 沿着根查找公共前缀 `"te"`，匹配成功。
2. 进入 `"te"` 节点，发现下一条边是 `"am"`。
3. 比较新词的剩余部分 `"a"` 和现有边 `"am"`。发现共享前缀只有 `"a"`，并不完全匹配整条边。
4. **触发分裂**：将原有的边 `"am"` **拆开**成两条边：`"a"` 和 `"m"`。
5. 新建一个中间节点，挂载边 `"a"`。在这个新节点下，一边是代表旧词的边 `"m"`（通往 `team`），另一边是代表新词的结束标记（通往 `tea`）。

最终结构变为：`te` -> `a` -> (分支：`m` 和 `End`)。这种动态调整保证了树始终处于压缩状态。

---

### 3. 优缺点再平衡

-   **优点（显著提升）**：
    -   **内存极省**：节点数量从“总字符长度”骤降到“分支节点数 + 叶子节点数”，在处理超长单词（如化学名词、URL路径）时优势巨大。
    -   **缓存友好**：访问边时直接跳跃多个字符，减少了指针追逐（Pointer Chasing），CPU缓存命中率更高。
-   **缺点（实现复杂度）**：
    -   **增删改复杂**：插入和删除时需要进行字符串比较、边分裂和边合并（删除时若产生单支链需反向压缩），代码量是普通 Trie 的几倍。
    -   **查找稍重**：在每条边上需要调用字符串比较函数（如 `memcmp`），而普通 Trie 只需比较单个字符（虽然时间复杂度量级相同，但常数因子略大）。

---

### 4. 经典落地场景（进阶版）

压缩字典树绝不是“学术玩具”，它在底层基础架构中出场率极高：

-   **IP 路由表（最长前缀匹配 LPM）**：路由器匹配目标 IP 时，需要在前缀树中找最长的匹配项。Radix Tree 压缩了二进制 IP 地址中连续的 0/1，使得路由查表速度极快，Linux 内核的 `fib_trie` 用的就是它。
-   **Redis 底层数据结构**：Redis 的 **Streams** 消息队列和部分内部命令（如 `CLUSTER SLOTS`）在管理键空间时，会使用 Radix Tree 来节省内存并快速范围查询。
-   **HTTP 路由框架**：Gin、Echo 等 Go 语言高性能 Web 框架，其路由匹配底层正是基于 Radix Tree。它能高效压缩 RESTful API 中的静态路径（如 `/user/info`），并快速区分静态段和参数段（如 `/:id`）。
-   **文件系统（FS）**：操作系统在目录项缓存（dentry cache）中，常利用此类结构快速根据路径查找 inode。

---

### 5. 顺带一提：Patricia Trie 的名字

它常被称为 **Patricia Trie**，这是“Practical Algorithm To Retrieve Information Coded In Alphanumeric”的缩写。这个名字强调了它的初衷——在实际的字母数字编码中高效检索信息，诞生于 1968 年，至今仍在发光发热。
