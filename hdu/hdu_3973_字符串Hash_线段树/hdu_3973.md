这题是一个很典型的 **字符串 Hash + 线段树维护动态字符串** 问题。

关键在于：

- 给定的单词集合 `{Wi}` 永远不变；
- 字符串 `S` 会发生**单点修改**；
- 每次询问需要判断当前的 `S[L..R]` 是否**恰好等于某个给定单词**。

因此没必要使用 AC 自动机。AC 自动机擅长在一个字符串中批量寻找模式串，但这里有动态修改，而且每次询问的是指定区间。

原题是 HDU 3973，题面给出的内存限制只有 32768 KB，所以也不适合把大量字符串或区间内容直接存在线段树里；只维护哈希值即可。

---

## 一、核心思路

定义字符串 Hash：

\[
H(s_1s_2\dots s_k)
=
(((v(s_1)\times B+v(s_2))\times B+v(s_3))\dots)
\]

其中：

\[
v('a')=1,\quad v('b')=2,\dots,v('z')=26
\]

例如：

\[
H("abc")=1\times B^2+2\times B+3
\]

这个 Hash 最大的好处是可以直接合并两个字符串。

如果：

- 左边字符串为 `A`
- 右边字符串为 `C`

那么：

\[
H(A+C)=H(A)\times B^{|C|}+H(C)
\]

这正好适合线段树。

---

# 二、线段树维护什么？

对于线段树的每个节点，维护：

```cpp
struct Node {
    int h1;
    int h2;
    int len;
};
```

这里使用**双 Hash**降低碰撞概率。

节点表示某个字符串区间：

```text
[l ........ r]
```

保存：

- `h1`：模 `1e9+7` 的 Hash
- `h2`：模 `1e9+9` 的 Hash
- `len`：字符串长度

假设左右儿子分别为：

```text
A
B
```

那么：

```cpp
res.h1 = A.h1 * pow1[B.len] + B.h1;
res.h2 = A.h2 * pow2[B.len] + B.h2;
```

取对应模数。

---

# 三、为什么区间 Hash 不需要再归一化？

这是线段树 Hash 相比 Fenwick Hash 很方便的地方。

比如查询：

```text
S[7..10] = "abcd"
```

线段树查询返回的就是：

\[
H("abcd")
\]

而不是：

\[
H("abcd")\times B^7
\]

因为在线段树合并过程中，我们始终按照：

```text
左字符串 + 右字符串
```

重新拼接 Hash。

因此可以直接与字典中：

```text
"abcd"
```

的 Hash 比较。

# 四、预处理所有 Wi

对于一个单词：

```cpp
string w;
```

直接：

```cpp
h = h * BASE + value(c);
```

求出双 Hash。

然后保存：

```text
(length, hash1, hash2)
```

为什么还要保存长度？

因为我们真正判断的是：

> 字符串是否完全相同。

即使两个不同长度字符串碰巧 Hash 相同，也不能认为它们相同。

因此使用：

```cpp
struct Key {
    int len;
    int h1;
    int h2;
};
```

放入 `unordered_set`。

注意，这里根本不用保存所有 `Wi`。

虽然：

\[
\sum |W_i|\le 2\times10^6
\]

但：

\[
n\le 10000
\]

最终只需要保存最多 10000 个 Hash。

---

# 五、修改操作

例如：

```text
C 4 b
```

只修改：

```text
S[4] = 'b'
```

在线段树中就是单点修改。

修改叶节点以后一路向上重新计算 Hash。

复杂度：

\[
O(\log |S|)
\]

---

# 六、查询操作

对于：

```text
Q L R
```

在线段树查询：

```cpp
Node cur = query(L, R);
```

得到：

```text
cur.len
cur.h1
cur.h2
```

然后检查：

```cpp
dictionary.count({cur.len, cur.h1, cur.h2})
```

即可。

复杂度：

\[
O(\log |S|)
\]

Hash 表查询期望：

\[
O(1)
\]

---

# 七、为什么线段树合并一定要注意顺序？

字符串 Hash 是**不可交换**的。

例如：

```text
"ab"
```

Hash 为：

\[
1B+2
\]

而：

```text
"ba"
```

Hash 为：

\[
2B+1
\]

所以：

```cpp
merge(left, right)
```

必须严格表示：

```text
left + right
```

不能交换左右顺序。

这是这类题非常容易写错的地方。

# 九、复杂度分析

设

\[
W=\sum |W_i|
\]

并令：

\[
N=|S|
\]

### 字典预处理

每个字符只参与一次 Hash：

\[
O(W)
\]

题目保证：

\[
W\le2\times10^6
\]

### 建立线段树

\[
O(N)
\]

### 单次修改

\[
O(\log N)
\]

### 单次查询

线段树：

\[
O(\log N)
\]

哈希表：

\[
O(1)
\]

期望复杂度。

所以总复杂度：

\[
\boxed{
O\left(
\sum |W_i|+|S|+m\log |S|
\right)
}
\]

空间复杂度：

\[
\boxed{O(n+|S|)}
\]

## 十、几个关键陷阱

这道题最值得注意的是下面几点：

1. **不是询问某个单词是否出现在 `S[L..R]` 中**，而是询问整个 `S[L..R]` 是否就是给定单词之一。
2. `S` 的下标明确从 **0 开始**，不用做 `+1` 转换。
3. Hash 合并有方向，必须是 `left + right`。
4. 字典单词可能比 `S` 长得多，但没有关系。字典 Hash 用 `h = h*BASE+c` 直接计算，不需要预处理到 200 万次幂；线段树只需要预处理到 `|S|`。
5. 不建议直接使用单 Hash。原来的很多老代码使用一个 `long long` Hash，但现在写的话用双模 Hash 更稳妥。
6. 不需要保存 200 万字符的整个单词集合，读一个算一个 Hash 即可。

所以这道题可以概括成一句话：

> **把“字符串是否相等”转化成“Hash 是否相等”，再利用 Hash 可以拼接的性质，用线段树维护动态字符串 S。**
