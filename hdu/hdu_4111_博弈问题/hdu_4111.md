这道题的难点在于：**数字 `1` 会破坏单纯的奇偶性分析**。如果没有 `1`，游戏基本上由“总和 + 合并次数”的奇偶性决定；但存在若干个 `1` 时，还会出现一个特殊的模 3 结构。

最终可以做到每组数据 **O(N)** 判定。

## 1. 状态分类

记：

- `c`：数字 `1` 的个数；
- `m`：大于 `1` 的数字个数；
- `S`：所有大于 `1` 的数字之和。

我们只需要这三个量，以及判断“大于 1 的部分是否恰好只有一个 `2`”。

完整的必败态（也就是轮到当前玩家时 Bob 型状态）可以分成两类。这个分类也是该题已知的完整 P-position 分类。

---

## 2. 特殊状态：只有 `1`，或者 `2 + 若干个 1`

先考虑：

```text
1,1,1,...,1
```

设有 `c` 个 `1`。

每次只能：

1. 删除一个 `1`；
2. 合并两个 `1` 得到一个 `2`。

再考虑：

```text
2,1,1,...,1
```

这两个状态族会形成一个模 3 的循环。

结论是：

> 如果状态是“全是 1”，或者“一个 2 加若干个 1”，那么当且仅当 `c % 3 == 0` 时为必败态。

注意这里第二种情况下 `c` 指的是 **1 的个数**。

例如：

```text
[2]             c=0   Bob
[2,1]           c=1   Alice
[2,1,1]         c=2   Alice
[2,1,1,1]       c=3   Bob
```

以及：

```text
[1]             c=1   Alice
[1,1]           c=2   Alice
[1,1,1]         c=3   Bob
[1,1,1,1]       c=4   Alice
```

为什么是模 3？

令

```text
U(c) = c 个 1
V(c) = 一个 2 + c 个 1
```

对于 `U`：

```text
U(c) -> U(c-1)       删除一个 1
U(c) -> V(c-2)       合并两个 1
```

于是：

- `U(3k+1)` 可以删除一个 `1` 到 `U(3k)`；
- `U(3k+2)` 可以合并两个 `1` 到 `V(3k)`。

所以它们都是必胜。

类似地：

- `V(3k+1)` 删除一个 `1` 到 `V(3k)`；
- `V(3k+2)` 把 `2` 减成 `1`，得到 `U(3k+3)`。

因此也是必胜。

而 `U(3k)`、`V(3k)` 的任何有效走法都会进入必胜态，所以它们是必败态。

---

# 3. 一般状态

排除上面两个特殊族，即：

- 至少有一个 `>1` 的数；
- 并且“大于 1 的部分”不是单独一个 `2`。

此时结论非常漂亮：

> 当前状态为必败态，当且仅当：
>
> ```text
> c 是偶数
> ```
>
> 并且
>
> ```text
> S + m - 1 是偶数
> ```

即：

```cpp
c % 2 == 0 && (S + m - 1) % 2 == 0
```

否则 Alice 必胜。完整分类可整理为这一形式。

---

## 4. 为什么会出现 `S + m - 1`

先暂时不考虑 `1`。

假设现在有：

```text
a1,a2,...,am
```

并且全部至少为 `2`。

所有石子的总和为 `S`。

### 操作一：减 1

总和：

```text
S -> S-1
```

因此

```text
S + m - 1
```

奇偶性翻转。

### 操作二：合并两堆

总和 `S` 不变，但是堆数：

```text
m -> m-1
```

所以：

```text
S + m - 1
```

同样翻转奇偶性。

因此这个量是这个游戏最核心的奇偶量。

如果 `1` 的数量是偶数，在非特殊情况下，这些 `1` 可以看成成对存在，第二个玩家总能利用另一只 `1` 抵消第一只 `1` 带来的异常操作。

例如对方删除一个 `1`，你也删除一个：

```text
... 1 1
 -> ... 1
 -> ...
```

对方把一个 `1` 合并到某个数 `x`：

```text
x,1,1
 -> x+1,1
 -> x+2
```

于是两个 `1` 被整体消掉，而核心奇偶关系保持不变。

所以一般状态最终由：

```text
1 的数量奇偶性
+
S + m - 1 的奇偶性
```

共同决定。

# 5. 为什么 `(2, 1, 1, ...)` 必须单独处理？

这是本题最容易 WA 的地方。

比如：

```text
2
```

显然 Bob 赢：

Alice 只能：

```text
2 -> 1
```

Bob：

```text
1 -> 0
```

Alice 无法操作。

但是：

```text
2 1 1
```

如果直接套一般公式：

```text
c = 2
m = 1
S = 2

S + m - 1 = 2
```

两个条件都是偶数，看起来应该 Bob 赢。

实际上：

```text
2 1 1
```

是 **Alice 必胜**。

Alice 可以把：

```text
1 + 1 -> 2
```

得到：

```text
2 2
```

而 `2 2` 是必败态。

所以：

> “唯一一个非 1 数字恰好为 2”

必须进入特殊的模 3 分类。

这正是这题最核心的坑。

# 6. 最终判定公式

设：

```cpp
cnt1 = 1 的个数
cntBig = >1 的个数
sumBig = >1 数字的总和
```

### 情况 1：全是 1

```cpp
cntBig == 0
```

Bob 当且仅当：

```cpp
cnt1 % 3 == 0
```

---

### 情况 2：只有一个非 1 数，并且它是 2

等价于：

```cpp
cntBig == 1 && sumBig == 2
```

因为非 1 数全部至少为 2。

Bob 当且仅当：

```cpp
cnt1 % 3 == 0
```

---

### 情况 3：一般情况

Bob 当且仅当：

```cpp
cnt1 % 2 == 0
&&
(sumBig + cntBig - 1) % 2 == 0
```

其余情况 Alice 赢。

---

# 7. 样例验证

### Case 1

```text
1 1 2
```

有：

```text
cnt1 = 2
cntBig = 1
sumBig = 2
```

属于：

```text
2 + 若干个1
```

因为：

```text
2 % 3 != 0
```

所以 Alice 赢。

---

### Case 2

```text
3 4
```

没有 `1`：

```text
cnt1 = 0
cntBig = 2
sumBig = 7
```

计算：

```text
S + m - 1
= 7 + 2 - 1
= 8
```

为偶数。

所以 Bob 赢。

---

### Case 3

```text
2 3 5
```

```text
cnt1 = 0
cntBig = 3
sumBig = 10
```

```text
S + m - 1
= 10 + 3 - 1
= 12
```

为偶数。

Bob 赢。

与样例一致。

## 9. 复杂度

每个数字只统计一次：

```text
时间复杂度：O(N)
空间复杂度：O(1)
```

全部测试最多也只是简单扫描。

这题最值得记住的地方就是两个层次的规律：

```text
一般状态：
偶数个 1 + (sumBig + cntBig - 1) 为偶数
    => Bob

特殊状态：
全 1
或者 2 + 若干个 1
    => 看 1 的数量 mod 3
```

尤其是 **`2 + 若干个 1` 不能套一般奇偶公式**，这是最主要的 WA 点。
