可以做到。关键是把“枚举 \(0\sim V\)”变成对若干个二进制整块的矩阵变换，整个状态规模只有

\[
2+\sum_{i=2}^n m_i\le 202.
\]

最终复杂度大约是预处理 \(O(60S^3)\)、每次询问 \(O(60S^2)\)，其中 \(S\le202\)，利用块下三角结构后常数很小。

## 1. 先化简 \(f(n)\)

由 Legendre 公式：

\[
f(x)=v_2(x!)=\sum_{k\ge 1}\left\lfloor\frac{x}{2^k}\right\rfloor
=x-\operatorname{popcount}(x).
\]

这里自然定义 \(f(0)=0\)。

因此：

\[
f(x)=x-\operatorname{popcount}(x).
\]

后面最重要的是它在二进制整块上的性质。

如果 \(B\) 是 \(2^k\) 的倍数，并且 \(0\le t<2^k\)，由于 \(B\) 的低 \(k\) 位全为 0，

\[
\operatorname{popcount}(B+t)
=
\operatorname{popcount}(B)+\operatorname{popcount}(t).
\]

所以

\[
\boxed{f(B+t)=f(B)+f(t)}.
\]

特别地：

\[
f(2^k+t)=2^k-1+f(t).
\]

这就是我们能处理 \(V\le10^{18}\) 的根本原因。

# 2. 如果直接从小到大扫描 \(x\)，其实状态非常少

暂时假设我们真的枚举

\[
x=0,1,\ldots,V.
\]

定义：

\[
d_0=1,\qquad
d_j=m_{j+1}\ (1\le j<n),\qquad
d_n=1.
\]

因此

\[
\sum_{j=0}^n d_j
=
2+\sum_{i=2}^n m_i
\le202.
\]

定义状态 \(g_j[r]\)。

对于 \(1\le j<n\)：

> \(g_j[r]\) 表示当前已经扫描过的数中，长度为 \(j\) 的合法前缀序列数量，并且最后一个数满足
>
> \[
> f(a_j)\equiv r\pmod {m_{j+1}}.
> \]

对于 \(j=n\)，因为不再需要给下一位检查模数，我们令 \(d_n=1\)，于是

\[
g_n[0]
\]

直接就是最终答案。

另外定义一个永远等于 1 的

\[
g_0[0]=1.
\]

---

## 3. 扫描一个新的数 \(x\)

设

\[
z=f(x).
\]

按 \(j=1,2,\ldots,n\) 的顺序执行：

\[
\boxed{
g_j[z\bmod d_j]
\mathrel{+}=
g_{j-1}[z\bmod d_{j-1}]
}
\]

为什么成立？

考虑所有满足

\[
a_j=x
\]

的新序列。

对于 \(j\ge2\)，它要求：

\[
f(a_{j-1})\equiv f(x)\pmod {m_j}.
\]

而

\[
d_{j-1}=m_j,
\]

因此恰好应该拿：

\[
g_{j-1}[f(x)\bmod m_j].
\]

特别注意我们必须按照 \(j\) 从小到大更新。

因为题目允许

\[
a_{j-1}=a_j=x.
\]

更新 \(g_j\) 的时候，\(g_{j-1}\) 已经把“末尾也是 \(x\)”的方案算进去了，恰好处理了相等的情况。

所以如果 \(V\) 很小，下面这个东西就是完整算法：

```cpp
g[0][0] = 1;

for (x = 0; x <= V; ++x) {
    z = f(x);
    for (j = 1; j <= n; ++j) {
        g[j][z % d[j]] += g[j - 1][z % d[j - 1]];
    }
}
```

问题只剩：

> 怎么一次性跳过 \(2^k\) 个 \(x\)？

# 4. 把扫描一个 \(x\) 看成线性变换

把所有 \(g_j\) 拼成一个大向量。

总维数

\[
S=\sum_{j=0}^n d_j\le202.
\]

扫描一个 \(x\) 的操作完全是线性的。

设 \(z=f(x)\)，记这个线性变换为 \(U(z)\)。

因为更新 \(j\) 时使用的是已经更新后的 \(j-1\)，所以一次 \(x\) 不只是让 \(j-1\to j\)，它可以在同一次更新中继续传播：

\[
j\to j+1\to j+2\to\cdots.
\]

因此，对于任意 \(i>j\)，矩阵的 \((i,j)\) 块只有一个元素为 1：

\[
U(z)_{i,j}
=
e_{z\bmod d_i}
e_{z\bmod d_j}^{T}.
\]

对角块全部是单位阵。

所以 \(U(z)\) 是一个**单位块下三角矩阵**。

---

# 5. 预处理长度 \(2^k\) 的整块

定义：

\[
T_k
\]

表示依次处理

\[
x=0,1,\ldots,2^k-1
\]

产生的总变换。

显然：

\[
T_0=U(f(0))=U(0).
\]

现在考虑 \(T_k\)。

前一半：

\[
0\le x<2^{k-1}
\]

对应 \(T_{k-1}\)。

后一半写成

\[
x=2^{k-1}+t.
\]

有：

\[
f(x)
=
f(t)+2^{k-1}-1.
\]

也就是说，后一半和前一半完全一样，只不过所有

\[
f(t)
\]

统一加了一个常数

\[
c=2^{k-1}-1.
\]

---

# 6. 加一个常数只意味着“循环移动模数桶”

对某一个状态块 \(g_j\)，它的下标是模 \(d_j\) 的。

如果所有 \(f(x)\) 都从 \(z\) 变成 \(z+c\)，那么使用的桶：

\[
z\bmod d_j
\]

变成

\[
(z+c)\bmod d_j.
\]

这只是把长度 \(d_j\) 的数组整体循环移动 \(c\) 位。

定义 \(P_c\) 表示“每个块分别循环移动 \(c\bmod d_j\)”。

那么：

\[
U(z+c)=P_cU(z)P_c^{-1}.
\]

因此一个完整区间的变换也满足：

\[
\operatorname{Shift}_c(T)
=
P_cTP_c^{-1}.
\]

于是：

\[
\boxed{
T_k
=
\operatorname{Shift}_{2^{k-1}-1}(T_{k-1})
\cdot T_{k-1}
}
\]

注意乘法顺序：先处理前半段，再处理后半段。

# 7. 为什么矩阵乘法并不贵？

所有 \(T_k\) 都是单位块下三角矩阵。

假设：

\[
C=AB.
\]

只存 \(i>j\) 的块，对角单位阵不存。

则：

\[
\boxed{
C_{i,j}
=
A_{i,j}
+
B_{i,j}
+
\sum_{j<t<i}A_{i,t}B_{t,j}
}
\]

所以完全不需要做普通的 \(202^3\) 全矩阵乘法。

令每个块大小为 \(d_i\)，实际乘法量是：

\[
\sum_{j<t<i}d_i d_t d_j.
\]

因为总大小只有 202、块数最多 21，非常可控。

# 8. 回答询问

我们需要处理：

\[
[0,V]
\]

总长度为：

\[
L=V+1.
\]

将 \(L\) 二进制拆分。

例如：

\[
13=8+4+1.
\]

那么依次处理：

\[
[0,8),\quad[8,12),\quad[12,13).
\]

对于任意当前块

\[
[B,B+2^k),
\]

由于 \(B\) 一定是 \(2^k\) 的倍数：

\[
f(B+t)=f(B)+f(t).
\]

因此这个块对应的变换就是：

\[
\boxed{
P_{f(B)}T_kP_{f(B)}^{-1}.
}
\]

这里：

\[
f(B)=B-\operatorname{popcount}(B).
\]

于是每个询问只需要最多处理约 60 个预处理好的矩阵。

---

# 9. 如何快速应用平移后的矩阵

没必要真的构造

\[
P_cT_kP_c^{-1}.
\]

对状态向量 \(v\)：

\[
P_cT_kP_c^{-1}v
\]

可以分三步：

1. 每个模数桶反向循环移动 \(c\)；
2. 应用 \(T_k\)；
3. 再循环移动回来。

复杂度仍然只有 \(O(S^2)\)。

---

# 11. 正确性总结

整个算法可以压成三个核心结论。

第一，顺序扫描数字 \(x\) 时，只需要维护

\[
d_0+d_1+\cdots+d_n
=
2+\sum m_i
\le202
\]

个状态，而不是维护所有模数的笛卡尔积。状态转移为：

\[
g_j[f(x)\bmod d_j]
\mathrel{+}=
g_{j-1}[f(x)\bmod d_{j-1}].
\]

第二，

\[
f(B+t)=f(B)+f(t)
\]

对任意按 \(2^k\) 对齐的区间成立，因此所有长度 \(2^k\) 的区间都有同一种变换，只差一个模数桶的循环平移。

第三，所有变换都是单位块下三角矩阵，因此预处理和询问都可以只操作块下三角部分，不需要普通的 \(202^3\) 全矩阵运算。

对于样例，程序得到：

```text
29
18
```

与题目一致。
