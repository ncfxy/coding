这道题是一个很典型的 **根号分治 / 轻重点优化动态图统计** 问题。

关键观察是：`Asksum` 只有三种本质不同的答案：

- \(S_{00}\)：两端都是黑色的边权和
- \(S_{01}\)：一黑一白的边权和
- \(S_{11}\)：两端都是白色的边权和

所以查询可以直接 \(O(1)\)。真正要解决的是：**一个点翻色后，怎样快速修改这三个答案。**

---

## 1. 一个点翻色会产生什么影响？

设当前要翻转节点 \(x\)。

记：

\[
sum_0(x)=\sum_{\operatorname{color}(v)=0}w(x,v)
\]

\[
sum_1(x)=\sum_{\operatorname{color}(v)=1}w(x,v)
\]

即 \(x\) 连向黑点、白点的边权和。

如果 \(x\) 从 `0 -> 1`：

- 原来连接黑点的边属于 `00`，现在变成 `01`
- 原来连接白点的边属于 `01`，现在变成 `11`

因此：

\[
S_{00}\mathrel{-}=sum_0
\]

\[
S_{01}\mathrel{+}=sum_0
\]

\[
S_{01}\mathrel{-}=sum_1
\]

\[
S_{11}\mathrel{+}=sum_1
\]

反过来 `1 -> 0`：

\[
S_{01}\mathrel{-}=sum_0,\quad S_{00}\mathrel{+}=sum_0
\]

\[
S_{11}\mathrel{-}=sum_1,\quad S_{01}\mathrel{+}=sum_1
\]

所以问题已经简化成：

> 每次 `Change x`，快速求出 \(sum_0(x),sum_1(x)\)。

---

# 2. 为什么不能直接遍历邻边？

如果每次修改直接遍历 \(x\) 的全部邻边：

```text
Change x -> O(deg(x))
```

最坏情况下存在一个度数 \(10^5\) 的点，并且修改它 \(10^5\) 次，总复杂度达到

\[
O(10^{10})
\]

显然无法接受。

于是使用**按度数轻重分治**。

---

# 3. 轻重点划分

取阈值：

\[
B\approx \sqrt{2m}
\]

定义：

- `deg[x] <= B`：轻点
- `deg[x] > B`：重点

由于所有节点度数之和为：

\[
\sum deg(x)=2m
\]

因此重点数量最多：

\[
H\le \frac{2m}{B}=O(\sqrt m)
\]

这正是根号分治能够成立的关键。

---

# 4. 重点维护什么？

对于每一个重点 \(h\)，维护：

```cpp
heavySum[h][0]
heavySum[h][1]
```

其中：

```text
heavySum[h][0] = h 连向所有黑点的边权和
heavySum[h][1] = h 连向所有白点的边权和
```

于是如果要修改的 \(x\) 本身是重点，可以直接得到：

```cpp
sum0 = heavySum[id[x]][0];
sum1 = heavySum[id[x]][1];
```

复杂度 \(O(1)\)。

如果 \(x\) 是轻点，则直接遍历邻边：

```cpp
for (edge : G[x])
    sum[color[to]] += w;
```

因为轻点度数最多 \(B\)，所以是：

\[
O(B)
\]

---

# 5. 节点翻色后，重点的信息怎么办？

这是这题最重要的第二部分。

假设节点 \(x\)：

```text
0 -> 1
```

那么所有与 \(x\) 相邻的重点 \(h\)，其：

```cpp
heavySum[h][0] -= w(h,x);
heavySum[h][1] += w(h,x);
```

因此对于每个节点 \(x\)，我们提前记录：

```cpp
heavyNeighbor[x]
```

表示：

> 所有与 \(x\) 相邻的重点，以及它们之间的边权总和。

由于重点总数只有 \(O(\sqrt m)\)，一次修改最多影响这么多个重点。

因此这部分也是：

\[
O(\sqrt m)
\]

---

## 6. 为什么需要把平行边合并？

题目没有明确保证不存在重边。

比如：

```text
x --(3)-- h
x --(5)-- h
```

那么 \(x\) 与重点 \(h\) 的总连接权应该是 `8`。

如果我们保存每一条边，那么极端情况下一个节点与同一个重点之间有 \(10^5\) 条平行边，一次修改又退化成 \(O(m)\)。

因此构造：

```cpp
heavyNeighbor[x]
```

之后，将相同重点的边权合并。

这样每个节点最多保存 \(H=O(\sqrt m)\) 个重点邻居。

---

# 7. 查询

维护三个变量：

```cpp
ans00
ans01
ans11
```

对于：

```text
Asksum A B
```

直接：

```cpp
if (A == 0 && B == 0) ans00
else if (A == 1 && B == 1) ans11
else ans01
```

因为无向边中：

```text
Asksum 0 1
Asksum 1 0
```

答案完全相同。

---

# 8. 复杂度分析

设：

\[
B=\Theta(\sqrt m)
\]

一次 `Change`：

- 轻点求邻边颜色和：\(O(B)\)
- 重点：\(O(1)\)
- 修改所有相邻重点的信息：最多 \(O(m/B)\)

所以：

\[
O\left(B+\frac mB\right)
\]

令：

\[
B=\sqrt m
\]

得到：

\[
O(\sqrt m)
\]

因此总复杂度：

\[
O((m+q)\sqrt m)
\]

更精确地说初始化接近 \(O(m\log m)\)，单次：

- `Change`：\(O(\sqrt m)\)
- `Asksum`：\(O(1)\)

对于 \(10^5\) 完全足够。

## 10. 样例过程

初始：

```text
1 --1-- 2 --2-- 3 --3-- 4

颜色：
0 0 0 0
```

因此：

\[
S_{00}=1+2+3=6
\]

查询：

```text
Asksum 0 0
```

输出：

```text
6
```

执行：

```text
Change 2
```

颜色变成：

```text
0 1 0 0
```

边分类：

```text
1-2 : 01，权 1
2-3 : 01，权 2
3-4 : 00，权 3
```

因此：

\[
S_{00}=3
\]

\[
S_{01}=1+2=3
\]

正好对应：

```text
3
3
```

## 11. 这题最容易错的地方

### `long long` 必须使用

单边：

\[
w\le 2^{31}-1
\]

一共有 \(10^5\) 条边，所以总边权可能达到约：

\[
2.1\times10^{14}
\]

`int` 一定溢出。

---

### `01` 和 `10` 是同一个答案

因为图是无向图。

所以：

```text
Asksum 0 1
Asksum 1 0
```

都直接输出 `ans01`。

---

### 重点自身翻色时，不需要修改自己的 `heavySum`

`heavySum[x][c]` 描述的是：

> x 的**邻居**有多少边权连向颜色 c。

现在只是 \(x\) 自己变色，它的邻居并没有变色，因此：

```cpp
heavySum[heavyId[x]]
```

自身不需要因为自己翻色而修改。

需要修改的是：

> 与 \(x\) 相邻的其他重点的 `heavySum`。

这是实现时非常容易写错的一点。

---

### 全局答案中的跨色边只能计算一次

不要维护：

```cpp
ans[0][1]
ans[1][0]
```

然后分别累加，否则容易把无向边重复计算。

直接维护：

```cpp
ans00
ans01
ans11
```

最清晰。

---

因此这题可以总结为：

> **维护三个全局答案 + 高度点维护按邻居颜色分类的边权和 + 根号分治处理翻色。**

这是动态“单点修改 + 邻接统计”里非常经典的一类技巧。
