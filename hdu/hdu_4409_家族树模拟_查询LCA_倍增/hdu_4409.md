这道题本质上是：

1. 根据名字前面的 `.` 还原一棵家族树；
2. 对每个节点的儿子按名字排序，即可回答 `L`；
3. `b name` 只需要查询父亲有几个儿子；
4. `c name1 name2` 是标准的 **LCA（最近公共祖先）**，用倍增做到 `O(log N)`。

`N,Q ≤ 30000`，因此直接建树 + 倍增 LCA 就足够了。

---

## 一、如何从输入还原家族树

名字前有多少个 `.`，就是这个人的深度（generation number）。

例如：

```text
Kongs
.son1
..son1son2
..son1son1
...child
.son0
```

深度分别为：

```text
Kongs       0
son1        1
son1son2    2
son1son1    2
child       3
son0        1
```

题目告诉我们：

> 一个人的父亲，是他上方最近的、generation 恰好少 1 的人。

所以读取的时候维护：

```cpp
last[d] = 最近出现的深度为 d 的节点
```

如果当前节点深度是 `d`，那么：

```cpp
parent = last[d - 1]
```

然后更新：

```cpp
last[d] = 当前节点
```

即可。

---

## 二、操作 `b name`

题目说：

> brothers 包括本人自己。

所以如果 `x` 的父亲是 `fa[x]`，那么答案就是：

```cpp
children[fa[x]].size()
```

例如一个父亲有三个儿子：

```text
A
B
C
```

那么查询 `b A`、`b B`、`b C` 都输出 `3`。

对于根节点 Mr. X，它没有父亲；如果真的查询，可以认为家谱中和它同代且同父的人只有它自己，因此输出 `1`。

---

## 三、操作 `L`

要求重新输出整棵家谱，并且：

> 亲兄弟之间按照名字字典序排序。

注意，只要求**同一父亲的儿子**排序。

因此我们建完树以后，对每个节点：

```cpp
sort(children[u].begin(), children[u].end(), 按名字比较);
```

然后从根开始 DFS：

```text
输出自己
依次 DFS 排序后的儿子
```

就得到了唯一正确的排列。

为什么？

因为 DFS 保证一个人的整个后代区域仍然连续，而兄弟之间按照名字依次访问，自然满足题目的排序规则。

---

## 四、操作 `c name1 name2`

就是求树上两个节点的 **最近公共祖先 LCA**。

因为：

```text
N <= 30000
Q <= 30000
```

如果每次暴力向父亲走，最坏会到：

```text
O(NQ)
```

不可接受。

使用倍增：

```cpp
up[u][j]
```

表示节点 `u` 向上走 `2^j` 步后的祖先。

由于：

```text
2^15 = 32768 > 30000
```

所以大约 16 层就够了，可以直接开 `LOG = 16` 或更保险开 `LOG = 17`。

构造：

```cpp
up[u][0] = father[u];

up[u][j] = up[ up[u][j-1] ][j-1];
```

每次 LCA 查询复杂度：

```text
O(log N)
```

---

# 五、LCA 的具体过程

设查询 `u, v`。

### 1. 先让两者深度相同

如果：

```text
depth[u] > depth[v]
```

利用二进制拆分，把 `u` 向上跳：

```cpp
diff = depth[u] - depth[v]
```

---

### 2. 如果已经相同

那么这个节点就是 LCA：

```cpp
if (u == v)
    return u;
```

---

### 3. 一起向上跳

从最大的 `j` 开始：

```cpp
if (up[u][j] != up[v][j]) {
    u = up[u][j];
    v = up[v][j];
}
```

最终 `u` 和 `v` 会停在 LCA 的两个不同儿子处，因此：

```cpp
return up[u][0];
```

---

# 六、复杂度

设总人数为 `N`，询问数量为 `Q`。

建树：

```text
O(N)
```

预处理倍增：

```text
O(N log N)
```

排序所有孩子：

```text
O(N log N)
```

单次 `b`：

```text
O(1)
```

单次 `c`：

```text
O(log N)
```

单次 `L`：

```text
O(N)
```

注意 `L` 本身就需要输出 `N` 行，因此 `O(N)` 已经是最优的。

总复杂度可以认为：

```text
O(N log N + Q log N + 实际输出量)
```

空间：

```text
O(N log N)
```

完全满足要求。

## 八、这里有一个值得注意的细节：不要递归 DFS

虽然普通 DFS 写起来很简单：

```cpp
void dfs(int u) {
    ...
    for (int v : child[u])
        dfs(v);
}
```

但这题的家谱完全可能是一条长度 `30000` 的链：

```text
A
.B
..C
...D
....
```

递归深度达到 30000 时，在部分 OJ 环境中可能造成栈溢出。

所以代码中的 `L` 使用了：

```cpp
vector<pair<int,int>> st;
```

进行**非递归 DFS**，更加稳妥。

另外，这题最大的关键点是：**输入本身其实已经隐式给出了一棵树**。`last[depth]` 可以在 `O(N)` 时间内把父子关系完整恢复出来；之后 `b` 是父节点度数，`c` 是 LCA，`L` 是对子节点排序后的先序遍历。把这三种操作分别对应到树的基本问题后，整体就很直接了。
