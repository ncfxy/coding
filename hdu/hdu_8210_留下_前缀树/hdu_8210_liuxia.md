# HDU 8210「留下」题解思路

## 题目在问什么（先用人话）

每个位置有两个数 `a_i`、`b_i`。给一个数 `x` 后，定义：

```text
f(i) = (a_i xor x) - b_i
```

对相邻的一对 `(i, i+1)`，如果满足：

```text
f(i) * f(i+1) <= 0
```

就说这对位置「合法」。

含义很简单：两个 `f` **一正一负**，或者 **至少一个是 0**（相乘 ≤ 0）。

每次询问给一个 `x`，要找**最左边**那个合法的 `i`；没有就输出 `-1`。

难点：`x` 一改，所有位置的 `f` 都会变。询问很多时，不能对每个 `x` 再扫一遍所有相邻对。

下面这套做法的核心思想是：

> 先搞清楚：对一个固定位置，哪些 `x` 会让 `f>0`、哪些会让 `f<0`、哪些会让 `f=0`。  
> 结果发现：这些 `x` 会按二进制前缀，聚成很少几块（大约 30 块）。  
> 再对每一对相邻位置，把「乘积 ≤ 0」的那些前缀块记下来。  
> 问某个 `x` 时，只要查它自己那条前缀链上的块就行。

---

## 1. 先只看一个位置：符号由谁决定？

固定位置 `i`，只关心 `f(i)` 是正、负还是零。

定义：

```text
c_i = a_i xor b_i
```

为什么要看 `c_i`？因为：

```text
a_i xor c_i = a_i xor (a_i xor b_i) = b_i
```

也就是说：**当 `x` 恰好等于 `c_i` 时，`a_i xor x` 正好等于 `b_i`，于是 `f(i)=0`。**

`c_i` 可以想成「让这个位置变成 0 的那个特殊 `x`」。

---

### 1.1 从高位往低位比 `x` 和 `c_i`

两个数比大小，本质是找**最高的不同位**。

这里比的是 `a_i xor x` 和 `b_i`。又因为 `b_i = a_i xor c_i`，可以证明：

- 只要 `x` 和 `c_i` 在某一位之前都一样，那么 `a_i xor x` 和 `b_i` 在这些位上也一样；
- **第一次出现不同的那一位**，就决定了谁大谁小；
- 再后面的低位，已经不影响符号了。

设第一次不同的位是第 `k` 位，那么符号表如下：

| `b_i` 的第 k 位 | 发生了什么 | `f(i)` |
|---|---|---|
| `0` | 这一位从本该是 `0` 变成了 `1`，`a_i xor x` 更大 | `> 0` |
| `1` | 这一位从本该是 `1` 变成了 `0`，`a_i xor x` 更小 | `< 0` |

总结成三句话：

1. `x = c_i` → `f(i) = 0`
2. `x` 与 `c_i` 第一次不同的那一位上，若 `b_i` 是 `0` → `f(i) > 0`
3. 否则 → `f(i) < 0`

---

### 1.2 用小例子感受一下

只看 3 位：

```text
a = 101
b = 011
c = a xor b = 110
```

按「`x` 和 `c=110` 第一次在哪一位不同」分类：

```text
x = 0**   最高位就不同；b 最高位是 0 → f > 0
x = 10*   第二位第一次不同；b 第二位是 1 → f < 0
x = 111   最低位第一次不同；b 最低位是 1 → f < 0
x = 110   完全相同 → f = 0
```

这里的 `0**`、`10*` 表示**二进制前缀块**：

```text
0**  = 所有最高位为 0 的 x（000,001,010,011）
10*  = 所有前两位为 10 的 x（100,101）
```

直觉：

> 一个位置，最多把全体 `x` 切成大约 30 个前缀块；  
> **同一块里，`f(i)` 的符号完全一样。**

这就是后面能预处理的原因：不用对每个 `x` 单独想，只要按前缀块想。

## 2. 一对相邻位置：哪些 `x` 让乘积 ≤ 0？

现在看相邻对 `(i, i+1)`。希望：

```text
f(i) * f(i+1) <= 0
```

也就是：

- 一正一负；或
- 至少一个为 0。

做法：从高位到低位，一边填 `x` 的下一位，一边跟踪两个位置各自的符号状态。

每个位置有三种状态：

```text
? ：到目前为止，x 还和 c 完全一样，符号还没定
+ ：已经确定 f > 0
- ：已经确定 f < 0
```

填下一位 `0` 或 `1` 时：

- 若还是 `?`，且这一位和对应 `c` 不同：
  - `b` 该位是 `0` → 变成 `+`
  - `b` 该位是 `1` → 变成 `-`
- 若这一位和 `c` 相同 → 继续保持 `?`
- 已经是 `+` 或 `-` 的，后面怎么填都不变

什么时候可以停？

```text
两个状态都定了：
    符号不同（一正一负）→ 当前这个前缀下的所有 x 都合法，记下来
    符号相同（同正或同负）→ 当前前缀整块都不合法，丢掉

已经填完 30 位，但还有 ?：
    说明 x 正好等于某个 c，对应的 f 为 0
    乘积一定 ≤ 0，这个单点合法，记下来
```

伪代码：

```text
dfs(depth, prefix, state1, state2):
    if state1 和 state2 都已确定:
        若 state1 != state2:
            记录「这个 prefix 是合法块」
        return

    if depth == 30:
        记录「这个 prefix 是合法块」
        return

    枚举下一位 go = 0 或 1:
        根据 go 是否与 c1/c2 当前位不同，更新两个状态
        dfs(depth + 1, 新前缀, 新状态1, 新状态2)
```

看起来像在搜一棵二叉树，但不会爆：

- 两边符号一确定就立刻停；
- 每个位置只有一条路能一直保持 `?`（必须一直跟着自己的 `c` 走）；
- 两个位置一起处理时，每一层真正还要继续往下走的分支只有常数条。

所以：**一对相邻位置，只会贡献 O(30) 个合法前缀块。**

## 3. 查询时怎么快速找到最左的 i？

长度为 `d` 的二进制前缀 `P`，对应一段连续的 `x` 区间：

```text
[P * 2^(30-d),  (P+1) * 2^(30-d) - 1]
```

例如前缀 `10`（长度 2）就是所有形如 `10***************...` 的数。

### 预处理

对每一对相邻位置 `(i, i+1)`：

1. 用上面的 DFS，得到若干合法前缀块；
2. 对每个前缀块，记一个值：

```text
best[前缀块] = 能让这个块合法的最小下标 i
```

同一个前缀块如果被很多对覆盖，只保留**最左**的那个 `i`。

### 回答一次询问 `x`

任何一个数 `x`，都属于它自己这条「从短到长」的前缀链：

```text
*（空前缀，全体）
x 的最高 1 位
x 的最高 2 位
...
x 的全部 30 位
```

一共 31 个前缀。对这 31 个前缀分别查 `best`，取最小值，就是答案。

为什么这样够？

> 任意一个「覆盖了这个 `x`」的合法前缀块，一定正好是这条链上的某一个前缀。  
> 不会漏，也不会多查无关的块。

---

## 4. 正确性直觉（串起来看）

对任意一对相邻位置：

1. DFS 把所有可能的 `x` 切成互不重叠的前缀块；
2. 同一块里，两个 `f` 的符号都固定；
3. 只把「乘积 ≤ 0」的块记进 `best`；
4. 因此这些块的并集，恰好就是这对位置合法的全部 `x`。

查询时：把所有「覆盖当前 `x`」的合法块对应的下标取最小，就是题目要的最左侧答案。

---

## 5. 复杂度

设二进制位数 `B = 30`：

| 部分 | 复杂度 |
|---|---|
| 每个相邻对产生的前缀块 | `O(B)` |
| 总预处理 | `O(nB)` |
| 每次询问 | 查 `B+1` 个前缀，`O(B)` |
| 总时间 | `O((n+q)B)` |
| 空间 | `O(nB)` |
