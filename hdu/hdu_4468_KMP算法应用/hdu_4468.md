这道题的难点在于：**不能枚举原串 \(s\) 的长度再验证**，那样最坏会退化到 \(O(n^2)\)。正确做法是把加密过程转换成字符串前缀拼接问题，再用 **动态 KMP + 贪心** 在线维护最短模板，整体做到 \(O(n)\)。这也是这道题的经典解法。

## 1. 先理解加密操作到底做了什么

设原串

\[
s=s_1s_2\cdots s_m
\]

当前字符串长度为 \(n\)，一次操作删除长度 \(k<m\) 的后缀，然后追加完整的 \(s\)。

删除之后保留的部分长度增加量为

\[
m-k
\]

而因为

\[
0\le k<m
\]

所以

\[
1\le m-k\le m
\]

换句话说，每执行一次操作，**上一次加入的 \(s\) 会留下一个非空前缀，然后后面重新接一个完整的 \(s\)**。

因此最终得到的 \(r\) 一定具有下面的形式：

\[
r=
\operatorname{pre}_{d_1}(s)+
\operatorname{pre}_{d_2}(s)+
\cdots+
\operatorname{pre}_{d_k}(s)+s
\]

其中

\[
1\le d_i\le |s|
\]

也就是说：

> **\(r\) 可以拆成若干个 \(s\) 的非空前缀，最后一段必须是完整的 \(s\)。**

例如样例：

```text
abcadabcabcad
```

最短

```text
s = abcad
```

可以拆成

```text
abcad | abc | abcad
```

其中 `abcad`、`abc` 都是 `abcad` 的前缀，最后一块恰好是完整的 `abcad`。这一等价转换也是这题动态 KMP 解法的基础。

---

# 2. 如果直接枚举 \(s\) 呢？

因为最终一定以完整的 \(s\) 结尾，所以假如枚举长度 \(m\)，那么 \(s\) 已经确定：

```text
s = r 的长度为 m 的后缀
```

然后可以判断前面的字符串能否拆成若干个 \(s\) 的前缀。

但是枚举

\[
m=1,2,\ldots,n
\]

每次再花 \(O(n)\) 判断，总复杂度

\[
O(n^2)
\]

而

\[
n\le 10^5
\]

肯定不行。

所以需要反过来：

> 一边扫描 \(r\)，一边动态构造“当前最短模板”。

---

# 3. 动态维护一个模板 `p`

暂时先忽略：

> 最后一段必须是完整的 \(s\)

这个限制。

扫描字符串 \(r\) 时，维护一个最短模板 `p`，希望已经扫描过的部分能够拆成：

```text
p 的前缀 + p 的前缀 + ...
```

同时维护 KMP 的失配数组。

设：

- `m`：当前模板 `p` 的长度
- `j`：当前末尾匹配了 `p` 的多少个字符
- `fail[x]`：长度为 `x` 的模板前缀的最长 proper border 长度
- `last`：最近一次出现完整 `p` 后的位置

---

# 4. 为什么这里能用 KMP？

假设当前已经匹配：

```text
p[0 ... j-1]
```

现在遇到新字符不匹配。

普通 KMP 会：

```cpp
j = fail[j];
```

这里这个操作有非常漂亮的含义。

假设

\[
b=fail[j]
\]

说明：

\[
p[0..b-1]
\]

同时是

\[
p[0..j-1]
\]

的后缀。

于是原本这一整块

\[
p[0..j-1]
\]

可以重新切成：

\[
p[0..j-b-1] + p[0..b-1]
\]

两块依然全部是 `p` 的前缀。

所以：

> **KMP 的 fail 跳转，本质上是在尝试重新选择“前缀块”的切分位置。**

这正好对应本题允许把字符串拆成任意长度的 `p` 的前缀。

因此在发生失配时，可以不断沿 `fail` 跳转，寻找另一种合法切法。

---

# 5. 如果 KMP 一直退到 0 都无法匹配呢？

例如当前模板是：

```text
p
```

而 `r[i]` 无论怎么调整切分方式，都不能成为 `p` 某个前缀的一部分。

那么：

> 当前模板已经太短了，必须把模板增长。

应该增长多少？

不能只加入 `r[i]`。

设最近一次完整匹配模板 `p` 的结束位置是：

```text
last - 1
```

那么从

```text
r[last ... i]
```

这一整段都应该追加到模板后面：

```text
new_p = old_p + r[last ... i]
```

为什么？

因为 `old_p` 在 `last` 之前刚刚完整出现了一次，那么从那里开始到当前位置的这段新信息，就是当前模板缺少的最短内容。

追加以后：

```text
new_p
```

恰好完整匹配到当前位置，因此：

```cpp
j = m;
last = i + 1;
```

---

# 6. `last` 有什么作用？

`last` 始终表示：

> 最近一次完整模板 `p` 匹配结束之后的位置。

也就是：

```text
... p | r[last ...]
        ^
       last
```

如果扫描结束以后

```text
last < n
```

说明最后还剩：

```text
r[last ... n-1]
```

这些字符。

但题目要求最终真正的 \(s\) 必须完整出现在字符串最后。

所以还必须把这部分加入 `p`：

```text
s = p + r[last ... n-1]
```

因此答案长度为

\[
|s|
=
m+(n-last)
\]

即：

```cpp
answer = m + n - last;
```

而且由于 `p` 本身恰好在 `last` 前完整出现，所以最终构造出的

```text
p + r[last ... n-1]
```

实际上就是 `r` 的一个后缀，满足真正的原串 \(s\) 必须是最终字符串后缀这一条件。

# 7. 看一下 `aab`

开始：

```text
r = aab
p = a
m = 1
last = 1
```

扫描第二个 `a`：

```text
a
```

完整匹配 `p`：

```text
a | a
```

所以

```text
last = 2
```

扫描 `b`：

`p="a"` 无论怎么调整都无法匹配 `b`。

于是追加

```text
r[last ... i] = "b"
```

得到

```text
p = "ab"
```

此时完整匹配：

```text
a | ab
```

扫描结束。

\[
answer=2
\]

实际上：

```text
s = ab
```

加密：

```text
ab
```

删除最后一个字符：

```text
a
```

再追加 `ab`：

```text
aab
```

完全正确。

# 8. KMP 的实现细节

这里采用：

```cpp
fail[len]
```

表示：

> 模板长度为 `len` 时，最长的真前后缀长度。

例如：

```text
p = ababa
```

则

```text
fail[5] = 3
```

因为最长 border 是：

```text
aba
```

模板是在运行过程中动态增长的，所以每追加一个字符，也同时动态计算新的 `fail`。

假设现在向长度为 `m` 的模板后面追加字符 `c`：

```cpp
p[m] = c;

int k = fail[m];

while (k > 0 && p[k] != c)
    k = fail[k];

if (p[k] == c)
    ++k;

fail[m + 1] = k;
++m;
```

就是标准 KMP prefix function 的在线版本。

# 10. 正确性总结

整个算法可以理解成三个关键结论：

1. **题目操作等价于前缀拼接**

   最终：

   \[
   r=P_1+P_2+\cdots+P_k+s
   \]

   每个 \(P_i\) 都是 \(s\) 的非空前缀。

2. **KMP 的 fail 跳转等价于重新切分前缀块**

   当当前切法失配时，通过 border 可以把已经匹配的一块重新拆成两个合法前缀，因此无需立刻扩大模板。

3. **所有 fail 都失败时才扩大模板**

   此时现有模板确实不可能继续表示当前前缀，最短的扩展就是加入：

   ```text
   r[last ... i]
   ```

   最后再加入 `last` 后面的残留部分，使最终模板完整出现在 \(r\) 的末尾。

## 11. 复杂度

KMP 的 `j` 每次下降都沿 `fail` 跳转，而模板的总增长长度最多为 \(n\)。

因此单组：

\[
\boxed{O(n)}
\]

空间：

\[
\boxed{O(n)}
\]

全部测试数据总字符数不超过 \(2\times10^6\)，完全可以通过。

样例得到：

```text
Case 1: 3
Case 2: 2
Case 3: 5
Case 4: 6
Case 5: 4
```

与题目一致。
