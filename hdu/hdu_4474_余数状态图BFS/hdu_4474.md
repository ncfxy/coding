这道题的关键是：**不要真的枚举 \(n,2n,3n,\dots\)**，因为答案可能有上万位。我们只需要关心一个数字对 \(n\) 的**余数**。

这是一个非常经典的 **“余数状态图 + BFS”** 问题。

## 1. 把数字压缩成余数

假设当前已经构造了一个十进制数 \(x\)，它模 \(n\) 的余数是：

\[
r=x\bmod n
\]

如果在末尾追加一个数字 \(d\)，新数字为：

\[
x'=10x+d
\]

那么：

\[
x'\bmod n=(10r+d)\bmod n
\]

所以我们根本不需要保存巨大的 \(x\)，只需要保存：

\[
0,1,\dots,n-1
\]

这 \(n\) 个余数状态。

如果最终到达余数 `0`，就说明构造出的数字是 \(n\) 的倍数。

---

## 2. 为什么使用 BFS？

题目要求的是**最小的正整数**。

比较两个正整数：

1. 位数少的一定更小；
2. 位数相同，则字典序小的更小。

因此我们：

- 按数字长度逐层 BFS；
- 每次尝试追加数字时按照 `0,1,2,...,9` 的顺序。

这样第一次到达余数 `0` 时：

- 位数一定最少；
- 在最短位数中，数字的字典序也最小；

所以就是题目要求的最小正整数。

注意第一位不能为 `0`。

---

## 3. 建图方式

设允许使用的数字集合为 `digits`。

状态 `r` 向：

\[
(10r+d)\bmod n
\]

连边，其中 \(d\) 是允许使用的数字。

但是并不需要真的建立所有边，BFS 时现场计算即可。

起点比较特殊。

我们枚举所有允许的非零数字：

```cpp
1,2,...,9
```

把

```cpp
d % n
```

作为初始状态。

---

## 4. 为什么一个余数只访问一次？

假设两个不同的数字 \(A,B\) 满足：

\[
A\bmod n=B\bmod n
\]

那么以后给它们追加完全相同的后缀，最终得到的余数也完全相同。

因此对于同一个余数，只需要保留**第一次 BFS 到达它的数字**。

由于 BFS 保证第一次到达的是：

- 长度最短；
- 相同长度中字典序最小；

后面的数字一定不可能更优。

所以最多访问 \(n\) 个状态。

复杂度：

\[
O(10n)
\]

每组数据 \(n\le 10^4\)，非常轻松。

---

## 5. 如何得到答案字符串？

答案可能非常大，肯定不能用 `long long` 保存。

对于每个余数记录：

```cpp
pre[r]   // 上一个余数
digit[r] // 从上一个余数追加了哪个数字
```

例如：

```text
... --追加3--> r1 --追加5--> r2 --追加7--> 0
```

从余数 `0` 一路沿着 `pre[]` 回溯，就能恢复答案。

---

## 6. 举个例子

假设：

```text
n = 7
禁止数字：7,8,9
```

允许：

```text
0,1,2,3,4,5,6
```

BFS 第一层：

```text
1, 2, 3, 4, 5, 6
```

对应余数分别为：

```text
1,2,3,4,5,6
```

然后从 `1` 开始尝试：

```text
10,11,12,...,16
```

只需要计算它们 `% 7` 后对应的状态。

一旦第一次得到余数 `0`，这个数字就是答案。

---

## 7. 一个容易写错的地方

不能直接写：

```cpp
queue<string>
```

然后不停：

```cpp
s + char(...)
```

虽然状态实际只有 \(n\) 个，但这样大量复制字符串，答案又可能有上万位，会造成很大的时间和内存开销。

正确方法就是代码里的：

```cpp
pre[]
lastDigit[]
```

每个状态只保存一个父节点和一位数字。

空间复杂度只有：

\[
O(n)
\]
